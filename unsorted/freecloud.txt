What is it?

Standard APIs and SDKs for apps to deploy server apps to a user-provided environment.

Why?


* get rid of app vendor lock (when developer of the app owns cloud and keeps user data)
* total privacy - server part of the app runs in user-owned isolated enviroment
* cost effiency - under-utilized server apps will cost nothing for each user
* same convenience for self-hosted and cloud provider options
* app developers can focus on making apps instead of managing infrastructure


What to run?

 - photos

Tier II apps - fediverse / p2p

Good use cases:
* single user app with synchronization needs (e.g. password manager)
* single user apps with sharing options (e.g. photo library)
* federated networks apps (Matrix, ActivityPub)



Отличие от Coolify

Coolify позволяет запускать любые приложения в контейнерах, а также управляет разными СУБД (Postgres, MySQL).

BYOC фокусируется на приложения со сверх-низкой утилизацией (V8, WASM) и на стандартизированных интерфейсах хранения (SQL, Blob, KV).

Это дает большие гарантии безопасности, чем контейнеры. И позволяет запускать серверную часть для десятков и сотен приложений на самой худой виртуалке.

Tech spec
---


Components:

1. Compliant private cloud instance (PCI)
	* DNS zone
	* OAuth2 provider
	* Runtime and storage orchestrator
	* Storage options:
		* sqlite
		* blob storage (s3)
			* content-addressable storage (ipfs)
	* Connectivity:
		* http(s) endpoint (domain/path routing)
		* private app<>backend endpoint
		* http client
2. SDK is integrated to client apps and provides authenticated deployment to a PCI
	* obtains a token unique to a single instance of the client app
	* can query PCI for backend instances (servlets)
	* can deploy the "servlets"
	* servlets are identified by their hash, making them content-addressable.
	* can talk to backend if authorized by user


Example user flow:

* user install "Flo - navidrome client"
* on welcome screen, app prompts: log in using your FreeCloud account
	1a user already has self-hosted instance, they type: "hasselbach.ru"
	1b user dont care much a selects "create account on FreeCloud.com"
	2 user sign-in, app receives a token
* app query if there is any "navidrome" backend out there
	* optionally, an app can support working with many backend, but not necessarily
* user authorizes connection of the app to the select backend
* the app allows music uploading

Future consideration:
---

Private cloud has potential to become standard backbone for fediverse.
A single user cloud could take over all social networks: X, Instagram, YouTube, Patreon.
User can manage all their content within their own cloud (whenever its their server or just paid account - migration is allowed and endorsed).

There are multiple problems to solve:
* Spam (drop non-authentic or not welcome communication)
* DDoS attacks (avoid ActivityPub feed to be overwhelmed)
* highload

Another perspective is layered solutions that can integrate on various layers of the PCI:
* protect blog with a x402 paywal or captcha (reverse proxies)
* setup CDN-proxy for all your apps as another app (DNS management)
* backup (storage provider)
